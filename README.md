# Чатный гусь 🪿

Telegram-бот с играми, викторинами, опросами и шуточными ответами от локальной модели. В группе откройте `/menu`, а для разговора упомяните бота или ответьте на его сообщение.

## Установка на Ubuntu 24.04

Запустите в интерактивной SSH-сессии. Установщик спросит токен BotFather, адрес API, ID модели и токен API, если включена авторизация.

```bash
curl -fsSL https://raw.githubusercontent.com/FunTom88/Humoristicson_bot/main/install.sh | sudo bash
```

Если вы уже вошли под root, используйте `bash` без `sudo`. Для запуска команды нужен `curl`. На сервере должны работать systemd и исходящий HTTPS к Telegram и PyPI.

Установщик создаёт Python-окружение в `/opt/humoristicson-bot` и включает службу `humoristicson-bot.service`. Настройки лежат в `/etc/humoristicson-bot/bot.env`, база SQLite — в каталоге состояния `/var/lib/humoristicson-bot`. При повторном запуске установщик использует существующие исходники и настройки.

## Подключение модели

Укажите адрес доступного с сервера native API LM Studio или Bionic. Бот отправляет запросы на `/api/v1/chat` с `reasoning: "off"`.

Для проверенной схемы с LM Link запустите API клиента на VDS и подключите его к тому же Link, где находится домашний Bionic. Оставьте домашний ПК включённым. В установщике примите значения по умолчанию, если API на VDS слушает `127.0.0.1:1234` и видит модель `google/gemma-4-12b-qat`.

```bash
curl -fsS --max-time 10 http://127.0.0.1:1234/v1/models
```

Установка автоматизирует развёртывание бота. LM Studio, вход в аккаунт и подключение LM Link настраиваются отдельно. При недоступности модели бот обслуживает меню и игры, а запросы к ИИ получают резервный ответ.

Перед переносом на другой VDS остановите старый экземпляр бота, если используете тот же Telegram-токен. Одновременно должен работать один клиент long polling на токен. Входящий порт для бота не требуется.

## Управление

```bash
sudo systemctl status humoristicson-bot.service
sudo journalctl -u humoristicson-bot.service -n 50 --no-pager
sudo systemctl restart humoristicson-bot.service
```

После изменения `bot.env` перезапустите службу. Для проверки в Telegram отправьте `/start`, затем обычное сообщение в личном чате. Код и шаблон настроек можно публиковать, а рабочий `bot.env` содержит секреты.

## Память и спор

Гусь помнит до 12 последних обращений и свои ответы в каждом чате и каждой теме Telegram. Общий контекст помогает ему различать авторов и продолжать разговор с несколькими участниками. История хранится в SQLite и истекает через сутки после последнего обращения. Обычные сообщения группы не сохраняются как отдельные обращения. Бот обрабатывает реплики, которые Telegram доставляет ему при действующих настройках приватности. Чтобы реплика точно дошла, ответьте на сообщение бота. При нажатии «Забыть мой контекст» удаляются ваши обращения и ответы на них в этом чате. Цитаты в чужих репликах и уже опубликованные сообщения могут остаться.

В режиме «Спор» Гусь ведёт отдельный контекст доводов и различает позиции участников. Нажмите «Спор» для случайной темы или введите `/debate@имя_бота ваша тема`. Отвечайте на сообщения ведущего. Автор спора может попросить итог через `/enddebate@имя_бота`. В личке суффикс с именем бота не нужен. Итог учитывает последние 12 обращений в рамках спора.

Для обновления установки из GitHub:

```bash
sudo git -C /opt/humoristicson-bot pull --ff-only
sudo systemctl restart humoristicson-bot.service
```
